### 关键踩坑（已写进 `server/docs/deployment.md`）
1. **OPcache `revalidate_freq=60`**：部署后立刻测试会跑旧字节码。部署脚本已内置
   `systemctl restart php-fpm-74` 刷新。
2. **宝塔全局 `fastcgi_intercept_errors on`**：PHP 的 404 被换成 HTML 错误页，
   破坏接口 JSON 契约。必须在 **server 段** 覆盖为 off。
3. **`try_files` 两个反直觉行为**：末尾是 URI 时必须带 `?$args`（否则查询串丢失）；
   中间参数命中文件时不内部重定向 → 曾把 `/changelog`、`/docs` 的 **PHP 源码直出**。
4. **不能写 `location ^~ /api/`**：`^~` 优先级高于 PHP regex location，
   try_files 回落到 index.php 后会当静态文件吐出源码。要用 `~ ^/api/(?!index\.php)`。
5. **宝塔默认 `location ~ .*\.(js|css)?$` 匹配所有路径**（`(js|css)?` 可选），
   正则优先于前缀 → 无扩展名路由全 404。解法：在 `extension/<站点>/` 用正则 location，
   且要写在它前面。
6. **`VARBINARY` 的 ip 列直接进 json_encode 会返回 false** → 响应体空白 + HTTP 200。
   `Respond::json()` 已加 `JSON_INVALID_UTF8_SUBSTITUTE` 兜底。
7. 测试脚本自身两个坑：`build_headers` 没把请求体传进去导致全部 40101；
   `http.Response(String,...)` 默认 latin1 编码中文会抛异常。

### 域名侧阻塞（需站长处理）
`chr.cc` 的 **DNSSEC 配置损坏**：注册局 DS 是 `2371 8 2`（算法 8 RSA），
Cloudflare 权威 DNSKEY 是算法 13（ECDSA）→ 做校验的公共 DNS **SERVFAIL**，
整个域名的所有子域都受影响。本机能打开只是因为本地解析器不校验/有缓存。
修复：注册商处删除 DS，或 Cloudflare 面板 Disable → 再 Enable DNSSEC。

### DNSSEC 问题定位到具体字段（2026-09-23 05:30 补充）

用 Cloudflare 的 KSK（`257 3 13 mdsswUyr3DPW…`）按 RFC 4034 反算确认：
- 假定算法 **13** → Key Tag **2371**、摘要 `E4CDAA45…8F3D13B3`，**与 Cloudflare 面板完全一致**
- 假定算法 **8** → Key Tag 2366、摘要 `03832E5E…`，完全不同

结论：**注册局的 key tag 与摘要都对，只有「加密算法」字段被存成了 8（RSA/SHA-256），
应为 13（ECDSA Curve P-256 with SHA-256）**。修复只需在注册商表单里改算法下拉框，
其余三个字段保持原值。注意注册商有「同 key tag 修改时摘要必须不同」的校验，
摘要不变可能被拒 → 需要「先删旧 DS 再新增」。
详见 `server/docs/extensibility.md` 第 6 节（含自算校验脚本与修复后验证命令）。

### DNSSEC 已修复并验证（2026-09-23 05:33）

站长在注册商处把 DS 的加密算法从 RSA/SHA-256 改为 ECDSA P-256，
验证结果：注册局 DS = `2371 13 2 E4CDAA45…`；`dig +dnssec @1.1.1.1` 与 `@8.8.8.8`
均为 **NOERROR + ad 标志**；`www`/`memo`/`ddz` 子域全部恢复。

**新增工具 `server/Scripts/check_dnssec.py`**：批量体检域名 DNSSEC，
能自动判定「DS 与 DNSKEY 不匹配」并算出正确的 DS 值；`--strict` 可挂监控。
默认清单：chr.cc / s2ss.com / wktyl.com / vogov.cn / xianyan.cc / iqg.cc / wyi.cc。
巡检结论：**chr.cc 正常，其余 6 个域名均未启用 DNSSEC，解析正常**。
建议把 `check_dnssec.py --strict` 加进每日定时任务（DNSSEC 故障是静默的）。
细节与「其他域名要不要开」的判断依据已写入 `server/docs/extensibility.md` 第 6 节。
