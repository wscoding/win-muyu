# 2026-09-24

## 修复：敲了木鱼但 /dashboard 不更新

### 根因（三层，接口本身一直是好的）

1. **客户端默认关闭上报**（主因）。`AppSettings.telemetryEnabled` 与
   `SettingsRepository.load()` 都默认 `false`，是 v2 后端下线时留下的。
   v3 上线后看板数据源全靠它 —— 默认关等于看板永远不动。
   线上表现：`devices` 表 0 行、`global_stats.taps = 0`。
2. **`POST /taps` 设备未注册返回 409，客户端静默丢弃**。启动时的 `/launch`
   偶发失败 → 本次运行所有敲击全丢，且没有任何提示。
3. **看板只有数字卡会 30 秒刷新**。趋势图 / 7 日明细 / 平台 / 版本 / 功德榜
   是服务端渲染一次，之后永不更新。

排查顺序记住：**客户端开关 → 上报是否发出 → 服务端是否收到 → 看板是否刷新**。
接口坏了反而是最不可能的那个。

### 改动

**服务端**（`server/`，已部署）
- 新增 `GET /api/v1/stats/overview`：一次返回 summary + trend + breakdown +
  leaderboard，供看板整页刷新（请求量降到 1/4，且是同一时刻快照）。
- `/taps` 响应新增 `global.taps_today`（全网今日），客户端可直接回显。
- 新增 `Stats::todayTotals()`。
- `dashboard.php` 加 `data-live-block` 标记 + 实时条（最后更新时间 / 立即刷新 / 暂停）；
  `site.js` 改为拉 overview 并重绘图表与 4 张表；`site.css` 加 `.live-bar` / `.ping`。

**客户端**（`lib/`）
- `telemetryEnabled` 默认改 `true`（老用户显式关过的不被升级改回来）。
- 上报三条触发线：攒够 batchSize / **空闲后首敲即报** / 超时兜底；
  新增 `tapMinIntervalMs`（默认 1000ms）防止自动敲击把 QPS 顶回 v2 量级。
  坑：`_lastFlushAt` 必须记**发起**时间，记成功时间会让连击时中间几下
  全误判成「空闲」而各发一次请求（单测因此从 2 个请求变成 7 个）。
- `/taps` 409 → 自动补一次 `/launch` 再重试（只补一次）。
- 上报失败最多自动重试 3 次。
- 新增 `fetchOverview / fetchLeaderboard / fetchProfile / setLeaderboardOptIn`。
- 新增页面：`ui/pages/leaderboard_page.dart`（功德榜 + 参与开关 + 昵称）、
  `ui/pages/sync_status_page.dart`（设备 ID / 最近上报结果 / 全网数字）；
  菜单加每日一签卡片，并修掉 v2 遗留文案「后端接口重写完成后才会真正生效」。
